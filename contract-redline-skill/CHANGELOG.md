# 合同修订 skill 更新日志

## [2.0.0-candidate.2] - 2026-07-20

### 架构调整
- 用一个稳定锚定的 `render_block` 替代同段多条字符串搜索operation
- 新增解析器所有的 `snapshot_id`、`block_id`、连续 `source_quote` 和完整block哈希
- 新增 `dependency_group` 分组预检：无关失败可隔离，关联法律修改保持原子性
- 新增受控证据目录，保留intents、完整计划、分组结果、可应用计划或错误
- 禁止为了定位、offset、XML或格式错误而改写法律意图

## [1.3.0-candidate.1] - 2026-07-20

### 新增
- 新增 `contract_pipeline.py snapshot`，从 DOCX 生成带源哈希、稳定段落 ID 和条款分组的合同快照
- 新增高层修订意图 schema，让 LLM 表达风险、期望法律效果和完整拟议文本，不再手写底层 operation
- 新增确定性差异编译器，把完整拟议段落拆成反向执行的原子 operation
- 新增 `prepare` 和 `preflight`，在临时副本模拟完整 apply 并核对最终可见文本
- 底层 apply 新增 `source_sha256` 防陈旧计划，并为非原子替换返回结构化错误码

### 限制
- 当前原型每个段落只允许一个 intent，跨段重构和复杂对象仍需批注或人工处理

## [1.2.0] - 2026-07-10

### 新增
- 新增事务式原地修订：所有 operation 先在自动清理的临时工作副本执行，全部通过后才原子替换原文件
- `inspect` 新增结构风险报告，覆盖已有修订与批注、表格与嵌套表格、页眉页脚、文本框、域、超链接、绘图、内容控件和占位内容
- `verify` 新增 ZIP/XML 完整性、修订 ID 唯一性、批注锚点关系、无效时间戳和未来时间戳校验
- 新增回归测试，覆盖原地事务、失败回滚、时间线、前导空格定位、元数据与文字颜色保真、表格批注

### 修改
- 默认任务完成后只保留原文件路径，不再生成额外修订稿副本；用户明确要求另存时仍可使用 `output`
- 修订时间改为自动上下文时间线：最后一处不晚于实际执行时间，operation 间隔按修改类型、文字长度和段落上下文长度动态计算，并叠加小幅自然波动
- 同一处替换产生的删除与插入使用同一时间，避免把一次修改拆成两个虚假的操作时点
- 默认仅更新 `lastModifiedBy`，不再覆盖原文档 `creator`
- 保留原 run 的文字颜色等格式属性
- 文本定位不再裁剪段首段尾空白，避免插入位置偏移
- 整段重写遇到已有修订、超链接、复杂对象或混合格式时主动拒绝，避免破坏原文结构

### 修复
- 修复多 operation 后续失败时可能留下半成品输出或部分覆盖原文件的问题
- 修复默认时间线可能生成晚于实际执行时刻的未来时间戳
- 修复计划缺少 `output` 时文档说明与脚本行为不一致的问题

## [1.1.7] - 2026-07-05

### 修改
- 删除 OfficeCLI 对照版后端，回到 `word_redline.py` 作为唯一执行引擎
- 按 `writing-great-skills` 重构 `SKILL.md`：顶层改为输入门槛、边界分流、审查档位、结构检查、闭环 operation、应用、校验的线性步骤
- 将重复业务规则继续收敛到 `references/`，顶层只保留必走 completion criteria，降低 sprawl 和 duplication
- 将默认输出改为副本，只有用户明确要求时才原地覆盖

## [1.1.6] - 2026-06-28

### 修复
- 修正 `plan-schema.md` 中关于多 operation 必须逐个 `in_place` 的过期说明；当前脚本支持一次按 `operations` 原始顺序逐条执行
- `word_redline.py apply` 兼容旧计划中的 `in_place: true` 写法，允许 `output` 省略或与 `source` 相同
- 多个 operation 不再按类型分组执行，避免同一段中后续操作依赖前序修订结果时定位失败

## [1.1.5] - 2026-06-01

### 修改
- 新增“交易参数保守规则”：金额、比例、费率、违约金标准、履行期限等不能机械禁止修改，也不能仅因立场主动调强；须结合交易标的金额、风险大小、履行难度、行业习惯和谈判空间综合评估必要性
- 明确禁止未做综合必要性判断就将违约金金额或比例上调、将履行期限压缩等过度强硬修改；必要性不足时默认改为批注提示用户确认商业口径
- 收紧动作说明，避免把“数字、期限优先使用 `replace_text`”误解为默认应调整交易参数

## [1.1.4] - 2026-05-31

### 新增
- 增加“原子化修订规则”：一个 `replace_text` 只能表达一个连续差异，纯新增/纯删除应分别使用 `insert_before` / `insert_after` / `delete_text`
- `word_redline.py apply` 默认拦截包含多个不连续变化的 `replace_text`，避免生成粗颗粒红线
- 为极少数确需局部重写的场景增加显式例外：`allow_non_atomic: true` + `atomic_reason`

### 修复
- 修复把纯新增包装成 `replace_text` 时可能产生空删除标记的问题
- 修复写回 `document.xml` 时 `mc:Ignorable` 中未使用前缀可能丢失命名空间声明的问题

## [1.1.3] - 2026-05-31

### 修改
- 增加“修订必要性闸门”，明确不是所有可优化表述都应进入正文修订，避免过度修订
- 调整精准修订要求：在“精修到位”之外增加“不改无实质收益内容”的约束
- 修订时间戳由固定 3 分钟间隔改为按合同长度和修订数量自适应，并加入自然浮动；短合同通常控制在半小时以内，长合同约 1 小时左右
- 明确默认修订起始时间为执行 `word_redline.py apply` 时的当前北京时间，并在 apply 输出中返回 `revision_start_time`

## [1.1.2] - 2026-05-21

### 修改
- 在 `SKILL.md` 中新增“精准精修到位”主入口硬约束，明确“少改”必须服从保护闭环，不得停留在表面降风险处理
- 在 `SKILL.md` 中明确禁止半截式修改：不能只删风险词、不补条件、例外、责任边界或程序前提
- 在 `references/review-framework.md` 中新增“同句/同款闭环检查”规则，要求每处修改后复核主体、条件、期限、标准、例外和责任后果是否完整
- 在 `references/failure-handling.md` 中新增“半成品修改不得提交”分流规则，要求无法改到位时升级处理或转为 comment

## [1.1.1] - 2026-04-27

### 新增
- 支持修订时间戳差异化：执行修订时可为每处修改设置 2–5 分钟间隔时间戳，避免统一时间

### 修改
- 增加修订时间戳间隔的处理提示

## [1.1.0] - 2026-04-14

### 修改
- 去除 `replace_paragraph` 对 macOS `osascript` 和本机 Microsoft Word 的运行时依赖
- `apply` 统一改为直接写入 DOCX XML 修订标记，`replace_text`、`replace_paragraph`、`add_comment` 走同一执行模型
- `verify` 新增 `total_revisions` 汇总字段，并将 `word_revision_count` 对齐为实际修订总数
- 更新 skill 文档、失败分流和计划 schema，明确默认不要求本机打开 Word

### 修复
- 修复非 Mac 或未安装 Word 环境下整段重写会直接失败的问题
- 修复说明文档把 Word 用户信息写成默认依赖的误导表述

## [1.0.0] - 2026-04-09

### 新增
- 新建“合同修订”skill，面向需要直接交付 Word 原生修订稿的合同修改场景
- 引入结构化修订执行流程：`inspect` / `apply` / `verify`
- 增加 `references/review-framework.md`，承载合同审查判断框架
- 增加 `references/failure-handling.md`，承载失败分流与边界处理规则
- 增加 `references/plan-schema.md`，定义结构化修改计划格式
- 新增 `scripts/word_redline.py` 作为 docx 精准修订执行引擎

### 修改
- 将原 `contract` skill 中适合复用的法律判断内容下沉为 references，而不是继续堆在 `SKILL.md`
- 将执行层与业务层拆分，避免文档说明和底层实现耦合

### 修复
- 避免旧版 skill 中内嵌代码示例与脚本实现漂移的问题
- 避免依赖写死旧路径的说明方式
